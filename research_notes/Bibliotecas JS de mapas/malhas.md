# Malhas territoriais para um HTML estático (Brasil e mundo)

Escopo: só dados (GeoJSON, TopoJSON, shapefile, tabela de códigos). Licença do arquivo geográfico é tratada à parte da licença de qualquer biblioteca JS que desenhe o mapa. Medições de tamanho abaixo foram feitas em 2026-10-08 por download ou `Content-Length`, salvo quando a fonte já publica o número.

## What is the license of IBGE malhas and of Natural Earth? Can they be copied into a repo and into an HTML report?

### Takeaway
The 2024 IBGE Malha Municipal Digital is released under CC BY 4.0, so it and derivatives may be copied into a repo or shipped beside an HTML report if attribution is kept. Natural Earth vector data is public domain and may be copied with no permission and no credit requirement. The npm package that wraps Natural Earth (`world-atlas`) is a separate ISC license on the package, not on the geometries.

### Cited Findings
- The IBGE document “Malha Municipal Digital e Áreas Territoriais 2024” says the IBGE distributes the MMD and products and information derived from it under a license compatible with Creative Commons BY 4.0, which allows users to distribute, remix, adapt, and build upon the product, including for commercial purposes, as long as credit is given to the original. Using the MMD means the user accepts the conditions and exempts the IBGE from liability. — [IBGE, liv102169.pdf](https://biblioteca.ibge.gov.br/visualizacao/livros/liv102169.pdf)
- The same 2024 note gives the technical profile of that mesh: scale 1:250,000 without point suppression; format Esri Shapefile; geodetic system SIRGAS 2000 (EPSG:4674); geographic coordinates (latitude and longitude); text encoding UTF-8. In 2024 the MMD has 5,573 geocodes, of which the note lists 5,569 municipalities, 1 Federal District (Brasília), and 1 state district (Fernando de Noronha, PE). The download path cited in the note is the malhas product page, edition 42093. — [IBGE, liv102169.pdf](https://biblioteca.ibge.gov.br/visualizacao/livros/liv102169.pdf)
- Official zip files on GeoFTP, measured by `Content-Length` on 2026-10-08: `BR_Municipios_2022.zip` 203,627,589 bytes, last-modified 28 Mar 2023; `BR_UF_2022.zip` 13,717,460 bytes, same day; `BR_Municipios_2024.zip` 208,153,231 bytes, last-modified 29 Apr 2025; `BR_UF_2024.zip` 14,674,008 bytes, same minute; `BR_Municipios_2025.zip` 237,062,431 bytes, last-modified 26 Feb 2026; `BR_UF_2025.zip` 14,814,182 bytes, same minute. Directory listings for `municipio_2022`, `municipio_2024`, and `municipio_2025` exist. 2022 zips sit under `.../municipio_2022/Brasil/BR/`; 2024 and 2025 zips sit directly under `.../municipio_YYYY/Brasil/`. — [IBGE GeoFTP, malhas municipais](https://geoftp.ibge.gov.br/organizacao_do_territorio/malhas_territoriais/malhas_municipais/)
- Natural Earth states that all versions of its raster and vector map data on its site are in the public domain; use in any manner is allowed, including modification, electronic dissemination, and offset printing; no permission is needed; crediting the authors is unnecessary. — [Natural Earth, Terms of Use](https://www.naturalearthdata.com/about/terms-of-use/)
- NACIS describes Natural Earth as a public-domain map dataset at 1:10 million, 1:50 million, and 1:110 million, free for any type of project, and points to the same terms. — [NACIS, Natural Earth](https://nacis.org/initiatives/natural-earth/)
- Official Admin 0 country shapefile zips on the NACIS CDN, `Content-Length` on 2026-10-08, all last-modified 13 May 2022: `ne_110m_admin_0_countries.zip` 214,976 bytes; `ne_50m_admin_0_countries.zip` 799,734 bytes; `ne_10m_admin_0_countries.zip` 4,930,492 bytes. — [Natural Earth 110m countries zip](https://naciscdn.org/naturalearth/110m/cultural/ne_110m_admin_0_countries.zip); [50m](https://naciscdn.org/naturalearth/50m/cultural/ne_50m_admin_0_countries.zip); [10m](https://naciscdn.org/naturalearth/10m/cultural/ne_10m_admin_0_countries.zip)
- `world-atlas` 2.0.2 on the npm registry is license ISC, description “Pre-built TopoJSON from Natural Earth”, unpacked size 8,219,628 bytes. The GitHub README says the repo is a redistribution of Natural Earth vector data version 4.1.0 as TopoJSON, in spherical coordinates, decimal degrees, quantized but not projected. Country `id` is the three-digit ISO 3166-1 numeric code; `properties.name` is the country name. — [npm registry, world-atlas](https://registry.npmjs.org/world-atlas/latest); [topojson/world-atlas](https://github.com/topojson/world-atlas)
- A separate maintained fork, `@cublya/world-atlas` 3.0.0-beta.2, is also ISC on the registry (unpacked 13,337,296 bytes). Its published readme says the build code stays ISC-licensed and that the artifacts are Natural Earth 5.1.2 quantized TopoJSON, with ISO fields including `isoA2`, `isoA3`, and `isoN3`. — [npm registry, @cublya/world-atlas](https://registry.npmjs.org/@cublya/world-atlas/latest); [@cublya/world-atlas readme mirror](https://npm.io/package/@cublya/world-atlas)

### Inferences
- IBGE CC BY 4.0 is enough to vendor a copy or a simplified derivative next to a generated HTML report. The obligation that matters in the report is attribution, not a ban on redistribution or on commercial use.
- The official municipal shapefile zips (about 194–226 MiB) are legal to copy and too heavy to inline in a static page. A small TopoJSON saved from the IBGE malhas API is a derivative of IBGE mesh data; the 2024 legal note covers derivatives of the MMD, so the same attribution should travel with the file. The API JSON itself was not observed to carry a license field.
- Natural Earth country files, and the TopoJSON `world-atlas` generates from them, can be committed and embedded. Keep the ISC notice on `world-atlas` package code if that package is redistributed as software; the geometry does not need Natural Earth credit, though the project offers a short credit line.
- `@cublya/world-atlas` is a beta fork. Its ISC line is the build, not a replacement for the Natural Earth public-domain grant.

### Gaps
- No 2025 or 2026 equivalent of liv102169.pdf was opened, so the CC BY 4.0 sentence is cited for the 2024 MMD, not re-proven for `BR_Municipios_2025.zip`. The 2025 zip is on GeoFTP (26 Feb 2026) but its feature count and legal note were not read.
- The malhas API responses do not declare EPSG in the opening bytes. The 2024 shapefile is EPSG:4674. It was not confirmed that the API mesh is that same edition.
- The `.prj` inside the Natural Earth zips was not opened here. `world-atlas` documents decimal degrees; an EPSG code for the zip was not copied from a Natural Earth page in this pass.
- A general IBGE institutional license page, separate from the 2024 MMD note, was not retrieved.

## What are realistic simplified file sizes for Brazil municipalities at a quality good enough for a choropleth (not cadastral precision)?

### Takeaway
For a national municipal choropleth, the practical file is about 1.4–2.1 MB of TopoJSON from the IBGE malhas API (5,570 polygons, 7-digit `codarea`). The cadastral-scale product is the GeoFTP shapefile at roughly 194–226 MiB zipped. State outlines for a UF choropleth are 31–99 KB at the lowest API quality and about 1.0 MB at maximum GeoJSON quality.

### Cited Findings
- IBGE v3 malhas API, Brazil, `intrarregiao=municipio`, `qualidade=minima`, `formato=application/json` (TopoJSON), downloaded 2026-10-08: 1,428,796 bytes. Topology object name `BRMU`, 5,570 geometries, every `properties.codarea` is 7 characters. Sample `codarea` `1100015`. Present: Fernando de Noronha `2605459`, São Paulo `3550308`, Brasília `5300108`. Absent: Boa Esperança do Norte `5101837`. URL: `https://servicodados.ibge.gov.br/api/v3/malhas/paises/BR?intrarregiao=municipio&qualidade=minima&formato=application/json`. — [IBGE malhas API v3](https://servicodados.ibge.gov.br/api/docs/malhas?versao=3)
- IBGE v2, `resolucao=5` (municipalities) TopoJSON, same day: `qualidade=1` 1,626,114 bytes; `qualidade=2` 1,691,860 bytes; `qualidade=3` 2,116,662 bytes. The `qualidade=1` file has 5,570 geometries, `codarea` of 7 digits, and a `centroide` of longitude/latitude (sample Alta Floresta D'Oeste, `1100015`). It includes `2605459` and excludes `5101837`. A secondary write-up of this API maps `qualidade` 1–4 from worst to best and `resolucao=5` to municipalities, and maps `formato=application/json` to TopoJSON and `application/vnd.geo+json` to GeoJSON. — [example v2 URL, qualidade=1](https://servicodados.ibge.gov.br/api/v2/malhas/BR?resolucao=5&qualidade=1&formato=application/json); [open-geodata/br_ibge_api](https://github.com/open-geodata/br_ibge_api)
- UF (state) meshes from the same v3 API, Brazil, `intrarregiao=UF`, downloaded 2026-10-08: TopoJSON `qualidade=minima` 31,464 bytes; GeoJSON `qualidade=minima` 98,502 bytes and 27 features with `codarea` `11, 12, 13, 14, 15, 16, 17, 21, 22, 23, 24, 25, 26, 27, 28, 29, 31, 32, 33, 35, 41, 42, 43, 50, 51, 52, 53`; GeoJSON `qualidade=intermediaria` 251,135 bytes; GeoJSON `qualidade=maxima` 1,001,279 bytes. Coordinates in the GeoJSON are decimal degrees (sample near −62, −13). v2 `resolucao=2&qualidade=1` TopoJSON was 66,649 bytes with `codarea` `"11"`. — [v3 UF minima GeoJSON](https://servicodados.ibge.gov.br/api/v3/malhas/paises/BR?intrarregiao=UF&qualidade=minima&formato=application/vnd.geo+json)
- Full-resolution municipal shapefiles are two orders of magnitude larger: 203,627,589 bytes (2022), 208,153,231 bytes (2024), 237,062,431 bytes (2025), as zipped shapefiles. UF shapefiles are about 13.1–14.1 MB zipped. The 2024 note says the published cartographic base matches scale 1:250,000 with no point suppression. — [IBGE GeoFTP](https://geoftp.ibge.gov.br/organizacao_do_territorio/malhas_territoriais/malhas_municipais/); [IBGE, liv102169.pdf](https://biblioteca.ibge.gov.br/visualizacao/livros/liv102169.pdf)
- `tbrugz/geodata-br` `geojson/geojs-100-mun.json` is 22,549,321 bytes on the GitHub contents API. The file starts as a GeoJSON FeatureCollection whose first feature is `id` `"1100015"`, name Alta Floresta D'Oeste, polygon in decimal degrees. The São Paulo file `geojs-35-mun.json` is 1,891,817 bytes. The README names the source as IBGE and the repo license as CC0 1.0. It does not state the mesh year or a simplification tolerance. — [tbrugz/geodata-br](https://github.com/tbrugz/geodata-br); [geojs-100-mun.json](https://github.com/tbrugz/geodata-br/blob/master/geojson/geojs-100-mun.json)
- `luizpedone/municipal-brazilian-geodata` minified national file `minified/Brasil.min.json` is 1,002,081 bytes, but the inspected payload is state polygons (`properties.UF`, `ESTADO`, `REGIAO`), not municipalities. Minified per-state municipal files are much larger: `MG.min.json` 8,062,243 bytes, `SP.min.json` 4,484,217, `MT.min.json` 4,060,115, `BA.min.json` 3,565,931. README: GeoJSON from IBGE, MIT license, copyright 2017 Luiz Pedone. — [luizpedone/municipal-brazilian-geodata](https://github.com/luizpedone/municipal-brazilian-geodata)
- `geobr` (R on CRAN 2.1.0, published 2026-09-20; Python 2.1.1 on PyPI, 2026-09-23) downloads official Brazilian spatial data rather than shipping the meshes inside the package (Python sdist 66.0 kB). `read_municipality` takes the 7-digit municipality code, defaults `simplified=TRUE`, and the docs say borders were simplified with `st_simplify` preserving topology at `dTolerance` of 100. - The BC250 (Base Cartográfica Vetorial Contínua, 1:250,000) edition announced 26 Nov 2025 is a different product from the Malha Municipal zip: it updates the municipal mesh, including Boa Esperança do Norte (MT), and is distributed as shapefile, GeoPackage, and PostGIS dump. No file size or license sentence for BC250 was retrieved. — [Agência IBGE, 26/11/2025](https://agenciadenoticias.ibge.gov.br/agencia-noticias/2012-agencia-de-noticias/noticias/45243-ibge-lanca-base-cartografica-atualizada-com-ajustes-de-fronteiras-e-malha-municipal)

### Inferences
- A choropleth that only needs recognizable municipal shapes should vendor the API TopoJSON (about 1.4 MB at `qualidade=minima` on v3, still about 2.1 MB at v2 `qualidade=3`), not the 200 MB shapefile. That is “good enough to color 5,570 areas,” not a boundary for cadastral or area measurement. The 2024 note’s 1:250,000 mesh with no point suppression is the large file.
- No measured national municipal polygon file in this pass was under 1 MB. The sub-1 MB and sub-100 KB figures are state outlines. Claims of an IBGE-derived municipal TopoJSON under 1 MB were not confirmed.
- `geobr` is useful as a pointer to year-versioned, simplified IBGE geometries in GeoPackage, which a JS page can download if the file URL is known. The package code being MIT does not relicense the IBGE geometries. GeoPackage is not what a bare static page loads without a parser; it would still need a GeoJSON or TopoJSON conversion before a typical browser map.

### Gaps
- `dTolerance` of 100 in the geobr docs has no unit in the text retrieved. File sizes of the simplified GeoPackages were not measured, and the current download host URL was not opened.
- Mesh year inside the live malhas API was not stated by the service. Counts show it is not the October 2026 TSE universe (it lacks `5101837`). Whether v3 `qualidade=minima` is topologically safe for a choropleth (shared borders, no gaps) was not tested, only downloaded.
- `BR_Municipios_2025.zip` was not unzipped, so its municipality count is unknown.
- `brazilian-geographic-data` 2.0.0 (npm, MIT, unpacked 6,678,466 bytes, published on the npm page as IBGE-sourced regions, states, cities, neighborhoods) was not unpacked, so it is unknown whether it contains polygons or only attribute lists. — [npm, brazilian-geographic-data](https://www.npmjs.com/package/brazilian-geographic-data); [registry latest](https://registry.npmjs.org/brazilian-geographic-data/latest)

## Which datasets join cleanly on IBGE 7-digit municipality codes versus TSE municipality codes?

### Takeaway
IBGE meshes join on the 7-digit `codarea` / GeoJSON `id`. TSE election files use a different 5-digit municipal code and a different numeric UF code. They do not match by string equality. The official crosswalk is TSE `municipio_tse_ibge.csv` (generated 04 Oct 2026): 5,571 rows, 7-digit `CD_MUNICIPIO_IBGE`, 5-digit `CD_MUNICIPIO_TSE`. In every row the two municipal codes differ and the two UF codes differ. Exterior (`ZZ`) is not in that table.

### Cited Findings
- IBGE’s own municipality code is 7 digits, the first two being the UF code. The public list is on the IBGE codes page (example: Acrelândia `1200013`). — [IBGE, Códigos dos Municípios](https://www.ibge.gov.br/explica/codigos-dos-municipios.php)
- The v3 minima municipal TopoJSON and the v2 `qualidade=1` TopoJSON both key polygons with 7-digit `codarea` (5,570 distinct values). The v3 UF GeoJSON uses 2-digit IBGE UF codes for 27 features, including `53` for DF. There is no TSE code in those properties. — [v3 municipal TopoJSON URL](https://servicodados.ibge.gov.br/api/v3/malhas/paises/BR?intrarregiao=municipio&qualidade=minima&formato=application/json); [v3 UF GeoJSON URL](https://servicodados.ibge.gov.br/api/v3/malhas/paises/BR?intrarregiao=UF&qualidade=minima&formato=application/vnd.geo+json)
- `geojs-100-mun.json` uses the same style of identifier: feature `properties.id` `"1100015"`. — [tbrugz/geodata-br](https://github.com/tbrugz/geodata-br/blob/master/geojson/geojs-100-mun.json)
- TSE open data publishes “Códigos oficiais de UF e municípios segundo o TSE e o IBGE”, source “Cadastro de eleitores”, created 24 Jun 2025, update frequency on demand. The resource URL is `https://cdn.tse.jus.br/estatistica/sead/odsele/municipio_tse_ibge/municipio_tse_ibge.zip`. — [Portal de Dados Abertos do TSE](https://dadosabertos.tse.jus.br/dataset/codigos-oficiais-de-uf-e-municipios-segundo-o-tse-e-o-ibge)
- That zip measured 139,020 bytes (`Content-Length` and download), last-modified 04 Oct 2026. Inside: `leiame.pdf` 60,546 bytes and `municipio_tse_ibge.csv` 520,088 bytes, latin-1, semicolon-separated. Header: `DT_GERACAO`, `HH_GERACAO`, `CD_UF_TSE`, `CD_UF_IBGE`, `SG_UF`, `NM_UF`, `CD_MUNICIPIO_TSE`, `NM_MUNICIPIO_TSE`, `CD_MUNICIPIO_IBGE`, `NM_MUNICIPIO_IBGE`. Data rows: 5,571. Generation stamp inside the file: `04/10/2026` `09:00:06`. All 5,571 `CD_MUNICIPIO_IBGE` values are 7 digits and unique. All 5,571 `CD_MUNICIPIO_TSE` values are 5 digits and unique. `SG_UF` has 27 values (26 states + DF) and no `ZZ`. — [municipio_tse_ibge.zip](https://cdn.tse.jus.br/estatistica/sead/odsele/municipio_tse_ibge/municipio_tse_ibge.zip)
- Worked pairs from that CSV: São Paulo, `SG_UF` SP, `CD_UF_TSE` 1, `CD_UF_IBGE` 35, `CD_MUNICIPIO_TSE` `71072`, `CD_MUNICIPIO_IBGE` `3550308`. Brasília, `CD_UF_TSE` 20, `CD_UF_IBGE` 53, TSE `97012`, IBGE `5300108`. Fernando de Noronha, PE, TSE `30015`, IBGE `2605459`. Boa Esperança do Norte, MT, TSE `73709`, IBGE `5101837`. Bujari, AC, TSE `01007` (quoted, leading zero), IBGE `1200138`, `CD_UF_TSE` 24, `CD_UF_IBGE` 12. Across all 5,571 rows, `CD_UF_TSE` ≠ `CD_UF_IBGE` and the municipal codes differ. `CD_UF_TSE` is 1 digit on 3,567 rows and 2 digits on 2,004 rows; `CD_UF_IBGE` is always 2 digits. — [municipio_tse_ibge.zip](https://cdn.tse.jus.br/estatistica/sead/odsele/municipio_tse_ibge/municipio_tse_ibge.zip)
- TSE divulgation spec EA12 (file dated 2026-05-22 in the fetched text) says the municipality configuration JSON lists, under each UF, `cd` as the municipality code with five digits, zero-padded, from the Electoral Justice registry, and `cdi` as the municipality identifier with five digits, zero-padded, according to the IBGE registry. For Exterior the UF abbreviation is `zz`. `mu` entries are municipalities or exterior localities. — [TSE EA12, configuração de municípios](https://www.tse.jus.br/eleicoes/eleicoes-2026-content/arquivos/divulgacao-de-resultados/tse-ea12-arquivo-de-configuracao-de-municipios)
- The 2022 consolidated-results spec uses the same pattern: UF abbreviation in lowercase, `zz` for Exterior, and the municipality code with 5 positions zero-padded. An example municipal filename is `sp71072-c0003-e999999-r.json`. — [TSE EA04](https://www.tse.jus.br/eleicoes/eleicoes-2022/arquivos/interessados/ea04-arquivo-de-resultado-consolidado)
- A 2026 EA11 layout summary also labels `mu.cd` as “Código TSE - 5 dígitos” and `mu.cdi` as “Código IBGE - 5 dígitos”. — [TSE EA11](https://www.tse.jus.br/eleicoes/eleicoes-2026-content/arquivos/divulgacao-de-resultados/tse-ea11-arquivo-de-configuracao-de-eleicoes)
- `kelvins/municipios-brasileiros` is points, not polygons: README says 5,570 records with IBGE code, name, UF, latitude, longitude, SIAFI, DDD, and timezone. `json/municipios.json` is 1,531,077 bytes; `json/estados.json` is 3,520 bytes. Repo license MIT, copyright 2016 Kelvin S. do Prado. The documented columns do not include a TSE code. SIAFI is a different identifier (example in the README: Abadia de Goiás, IBGE `5200050`, SIAFI `1050`). — [kelvins/municipios-brasileiros](https://github.com/kelvins/municipios-brasileiros)
- Nexo, citing the existence of parallel codes, notes that IBGE’s 7-digit code is widely used but is not the only official code: Banco Central, SIAFI, and TSE each have their own, and published a correspondence among them. — [Nexo Jornal, 12/09/2025](https://www.nexojornal.com.br/grafico/2025/09/12/codigo-do-ibge-para-estados-e-municipios-como-funciona-codificacao)

### Inferences
- Join path for a municipal choropleth of TSE results: TSE 5-digit code → `municipio_tse_ibge.csv` → `CD_MUNICIPIO_IBGE` → mesh `codarea` or `properties.id`. Do not zero-pad or truncate the 7-digit code to compare it with `CD_MUNICIPIO_TSE`. Do not join UF colors on `CD_UF_TSE`; use `SG_UF` or `CD_UF_IBGE`.
- The divulgation field `cdi` is specified as five digits “according to IBGE”. That is not the 7-digit `codarea`. Until a live `mun-e*-cm.json` is inspected, `cdi` should not be used as the mesh key. The open-data CSV is the crosswalk that actually contains the 7-digit code.
- The API mesh (5,570, has Noronha, lacks Boa Esperança do Norte `5101837`) will fail to draw that one MT municipality present in the 04 Oct 2026 TSE table (5,571 rows). The 2025 GeoFTP zip is the candidate newer geometry; it was not checked for `5101837`.
- `kelvins` centroids can label or dot a municipality after an IBGE-code join. They cannot fill a choropleth and cannot locate TSE exterior polling places.

### Gaps
- `leiame.pdf` inside the TSE zip was not read, so any license or methodology note in it is unknown. No TSE open-data license page was retrieved; the file is publicly downloadable, which is not the same as a stated redistribution license.
- No sample 2026 divulgation JSON was downloaded, so the real width and contents of `cdi` were not compared with the spec’s “five digits”.
- Exterior localities: EA12 defines `zz` and `mu` records for locais do exterior, but `municipio_tse_ibge.csv` has zero `ZZ` rows. No GeoJSON of consulates or of overseas polling places was found in the sources opened. A world-country polygon set does not locate those voters.
- Whether older TSE result files (boletim de urna, votação por seção) use the same 5-digit `CD_MUNICIPIO_TSE` as this October 2026 crosswalk was not re-checked against a 2022/2024 leiame in this pass. The EA04 spec and the `sp71072` filename are consistent with that 5-digit code for São Paulo.

## Is there a maintained world country TopoJSON with ISO 3166 codes, small enough to embed?

### Takeaway
Yes. `world-atlas` 2.0.2 `countries-110m.json` is 107,761 bytes with ISO 3166-1 numeric ids, and `countries-50m.json` is 756,420 bytes. Both are small enough to embed. Numeric ids are not alpha-2. For alpha-2 keys, `@rembish/iso-topojson` 1.4.0 `iso-a2.json` is 208,582 bytes and 250 features, with the npm license field set to CC-BY-4.0. The 110m world-atlas file has 177 polygons, so it is not a complete ISO country list.

### Cited Findings
- Files downloaded from jsDelivr for `world-atlas@2.0.2` on 2026-10-08: `countries-110m.json` 107,761 bytes; `countries-50m.json` 756,420 bytes; `countries-10m.json` 3,661,071 bytes; `land-110m.json` 55,207 bytes. `countries-110m.json` is a TopoJSON Topology with objects `countries` (177 geometries) and `land` (1). Sample country: `id` `"242"`, `properties.name` `"Fiji"`. — [countries-110m.json](https://cdn.jsdelivr.net/npm/world-atlas@2.0.2/countries-110m.json); [countries-50m.json](https://cdn.jsdelivr.net/npm/world-atlas@2.0.2/countries-50m.json); [countries-10m.json](https://cdn.jsdelivr.net/npm/world-atlas@2.0.2/countries-10m.json)
- The `world-atlas` README defines those three country files as 1:110m, 1:50m, and 1:10m derivatives of Natural Earth Admin 0, decimal degrees, and sets `id` to ISO 3166-1 numeric. Package version on npm is 2.0.2, license ISC, unpacked 8,219,628 bytes. README pins Natural Earth 4.1.0. — [topojson/world-atlas](https://github.com/topojson/world-atlas); [npm registry](https://registry.npmjs.org/world-atlas/latest)
- `@rembish/iso-topojson` 1.4.0, npm page published 2026-03-15: TopoJSON keyed by ISO 3166-1 alpha-2, 250 polygons. The readme table lists `iso-a2.json` 204 KB, `iso-a2-markers.json` 245 KB, `iso-a2-markers-biomes.json` 322 KB. Properties include `iso_a2`, `iso_a3`, `iso_n3`, `name`, `sovereign`, and `type`. The readme says overseas territories are separate polygons, unlike `world-atlas`, which merges them into sovereign states and uses numeric codes. CDN download on 2026-10-08: `iso-a2.json` 208,582 bytes; `iso-a2-markers.json` 250,534 bytes. Parsed `iso-a2.json` has one object `merged` with 250 geometries; sample Andorra `iso_a2` `AD`, `iso_a3` `AND`, `iso_n3` 20. Registry and `package.json` `license` field: `CC-BY-4.0`. Unpacked size 797,308 bytes. The same npm readme opens with the sentence “Public-domain TopoJSON world map”. — [npm @rembish/iso-topojson](https://www.npmjs.com/package/@rembish/iso-topojson); [package.json on jsDelivr](https://cdn.jsdelivr.net/npm/@rembish/iso-topojson@1.4.0/package.json); [iso-a2.json](https://cdn.jsdelivr.net/npm/@rembish/iso-topojson@1.4.0/iso-a2.json)
- `@cublya/world-atlas` 3.0.0-beta.2 documents a UN-style view in which `countries-10m.json` and `countries-50m.json` include 193/193 UN members and 2/2 observer states, while `countries-110m.json` includes 165/193 and 1/2. It says to use 10m or 50m when complete coverage matters. Country fields include numeric `id` plus `isoA2` / `isoA3` / `isoN3`. Individual file sizes of that beta were not measured; the tarball unpacked size is 13,337,296 bytes. — [@cublya/world-atlas](https://npm.io/package/@cublya/world-atlas)
- Natural Earth country zips at the three scales are 214,976, 799,734, and 4,930,492 bytes and are public domain, so a page can also embed a converted TopoJSON made from them. — [Terms of Use](https://www.naturalearthdata.com/about/terms-of-use/); [110m zip](https://naciscdn.org/naturalearth/110m/cultural/ne_110m_admin_0_countries.zip)

### Inferences
- For a small static report, embed `countries-110m.json` (108 KB) or `countries-50m.json` (756 KB) from `world-atlas` 2.0.2. Join countries on ISO numeric `id`, zero-padded to 3 digits (`"076"` for Brazil if the consumer uses numeric ISO; the file’s sample id is an unpadded-looking string of three digits, `"242"`). Do not expect alpha-2 in this file.
- 177 features at 110m is a cartographic subset. It will omit small states. That is acceptable for a world locator, not for a complete ISO join.
- If the report must key on alpha-2, `@rembish/iso-topojson` is the small file (about 209 KB) and is maintained as of March 2026. Because `package.json` says CC-BY-4.0 while the readme says public domain, ship it only with attribution until that conflict is resolved. The geometries’ upstream license was not separately audited.
- `countries-10m.json` at 3.7 MB and the `@cublya` unpacked tree at 13.3 MB are still downloadable, but they are no longer “embed without thinking” for a single HTML file. `@cublya` is beta.

### Gaps
- Feature counts for `world-atlas` `countries-50m.json` and `countries-10m.json` were not counted, only byte sizes. Completeness claims for 50m/10m in this note are from `@cublya`’s own build, not from `world-atlas` 2.0.2.
- The `@rembish` readme’s “public domain” sentence and the SPDX `CC-BY-4.0` field were not reconciled against a LICENSE file body.
- No source checked here gives an ISO code on a TSE `ZZ` locality. A country TopoJSON cannot be joined to exterior votes without another table of country names or ISO codes from the TSE exterior file, which was not downloaded.

## Which sources are too large or too restrictively licensed for a static report?

### Takeaway
Skip the official municipal shapefile zips (194–226 MiB), `datamaps` (137 MB unpacked, and it is a drawing library), the 22.5 MB `geodata-br` national GeoJSON unless a separate download is acceptable, and the archived fititnt collection (ODbL badge plus an internally uncertain license). Prefer the IBGE API TopoJSON for municipalities, the IBGE API UF file for states, and `world-atlas` 110m or 50m for countries. Several npm names in the brief are not published.

### Cited Findings
- Too large to inline, legal to copy with attribution if they are the 2024 MMD or a derivative of it: `BR_Municipios_2024.zip` 208,153,231 bytes; `BR_UF_2024.zip` 14,674,008 bytes; 2022 and 2025 municipal zips 203,627,589 and 237,062,431 bytes. Scale of the 2024 publication is 1:250,000, shapefile, EPSG:4674. — [GeoFTP](https://geoftp.ibge.gov.br/organizacao_do_territorio/malhas_territoriais/malhas_municipais/); [liv102169.pdf](https://biblioteca.ibge.gov.br/visualizacao/livros/liv102169.pdf)
- `datamaps` 0.5.10 on npm is license MIT, description “datamaps with d3.js”, unpacked size 137,455,952 bytes. The npm file listing shows a `dist/` of about 33.5 MB. This is a JavaScript map library that bundles TopoJSON, not a small data file. The license of the bundled geometries was not opened. — [npm datamaps](https://www.npmjs.com/package/datamaps); [registry latest](https://registry.npmjs.org/datamaps/latest)
- `fititnt/dados-referenciais-abertos` (successor of the archived GIS Dataset Brasil) shows an ODbL-1.0 license badge. The README says a DbCL license is suggested because the original producers did not state a license clearly, and that the initial shapefiles came from brasilemcidades.gov.br, a site the README marks unavailable. The project site says the content was archived on 31 May 2022 and will not be updated. ODbL is a share-alike license. — [fititnt/dados-referenciais-abertos](https://github.com/fititnt/dados-referenciais-abertos); [archived project site](https://fititnt.github.io/gis-dataset-brasil)
- `tbrugz/geodata-br` is CC0 on the repo and 22,549,321 bytes for the national municipal GeoJSON, with IBGE named as the source and no year. A CC0 notice added by a reuploader does not remove the attribution duty on the 2024 IBGE MMD if the geometry is a substantial copy of that product. The file is usable as a download, heavy to inline. — [tbrugz/geodata-br](https://github.com/tbrugz/geodata-br); [IBGE CC BY 4.0 text](https://biblioteca.ibge.gov.br/visualizacao/livros/liv102169.pdf)
- npm registry returned 404 for the package names `br-atlas`, `geojson-brazil`, and `brazil-geojson` (request to `/latest` on 2026-10-08). — [registry br-atlas](https://registry.npmjs.org/br-atlas/latest); [registry geojson-brazil](https://registry.npmjs.org/geojson-brazil/latest); [registry brazil-geojson](https://registry.npmjs.org/brazil-geojson/latest)
- GitHub `carolinabigonha/br-atlas` is a generator (BSD 3-Clause on the repo) that builds TopoJSON/GeoJSON from IBGE by running `make`; it is not a published npm package under that name. `mtrovo/br-atlas` is MIT, four commits visible in the search snapshot, and its README says the topology is the IBGE 2017 edition, quantized and projected with `d3.geoMercator` into a 960×960 viewport, not left in geographic coordinates. — [carolinabigonha/br-atlas](https://github.com/carolinabigonha/br-atlas); [mtrovo/br-atlas](https://github.com/mtrovo/br-atlas)
- GitHub `filipemeneses/geojson-brazil` says the meshes come from the IBGE data-service API and lists resolutions from country down to municipalities. The repository about-text retrieved did not show a license. — [filipemeneses/geojson-brazil](https://github.com/filipemeneses/geojson-brazil)
- `brazilian-boundaries` 1.0.0 is MIT on npm. The GitHub README says the fetched data comes from `luizpedone/municipal-brazilian-geodata` and that the package itself is MIT. Unpacked size was null in the registry payload. It is a loader over that older IBGE-derived GeoJSON, not a newer mesh. — [ythecombinator/brazilian-boundaries](https://github.com/ythecombinator/brazilian-boundaries); [registry](https://registry.npmjs.org/brazilian-boundaries/latest)
- `geobr` does not vendor the national municipal GeoPackage inside the CRAN/PyPI package (Python release files are 66 kB sdist and a 53 kB wheel). A JS report cannot `import` the R package. The geometries are downloadable official files in GeoPackage, CRS 4674, with a simplified option, which is attractive only after conversion to GeoJSON or TopoJSON. An older issue (March 2025) reported 404s for some `metadata_simplified_municipality_*.csv` URLs on the `ipeaGIT/geobr` GitHub path, so the download layout has already broken once. — [PyPI](https://pypi.org/project/geobr/); [CRAN](https://cran.r-project.org/package=geobr); [issue 382](https://github.com/ipea/geobr/issues/382)
- Point file, not a boundary: `kelvins` `municipios.json` at 1,531,077 bytes is small enough to embed and is MIT at the repo layer, but it is centroids keyed by IBGE code, with no TSE code and no exterior points. — [kelvins/municipios-brasileiros](https://github.com/kelvins/municipios-brasileiros)

### Inferences
- For this report, the files that are both small and cleanly licensable are: IBGE API UF TopoJSON (~31 KB) or GeoJSON (~99 KB) for the 27 UFs; IBGE API municipal TopoJSON (~1.4–2.1 MB) for the choropleth; `world-atlas` `countries-110m.json` (108 KB) or `countries-50m.json` (756 KB) for the world. Attribute IBGE. Natural Earth credit is optional.
- Do not vendor fititnt. The project is archived, the stated license is unstable (ODbL badge vs a suggested DbCL vs “maybe public domain”), and ODbL share-alike is a poor fit for dropping a file next to a generated report.
- Do not treat `datamaps`, `br-atlas`, or `geobr` as the data payload. `datamaps` is a renderer with a huge bundle. `br-atlas` is either a build script or a 2017 Mercator topology. `geobr` is an R/Python downloader.
- The TSE crosswalk zip (139 KB) is the right companion file for the join and is small enough to ship. Its license text was not found; it is an official open-data download, not a geometry.

### Gaps
- `filipemeneses/geojson-brazil` has no license in the material retrieved, and its file sizes were not measured. It should not be copied until a LICENSE file is confirmed.
- `brazilian-geographic-data` contents (polygons or not) and the mesh year were not verified.
- No redistributable point layer for TSE UF `ZZ` (Brazilians voting abroad) was found. The boundary sets above stop at the national frontier plus a world-country mesh. Exterior remains a non-polygon TSE code (`zz` in the divulgation specs) with no row in `municipio_tse_ibge.csv`.
