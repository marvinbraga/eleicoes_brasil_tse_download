# Fitness of JS map libraries for one self-contained Brazil choropleth HTML

Scope of this note: whether Leaflet, MapLibre GL JS, Apache ECharts, D3, and the usual hosted-map options can draw a party-share choropleth of Brazilian UFs and municipalities inside one HTML file that a Python script writes. Engines, mesh files, and chart libraries are covered by other researchers. Pages were read on 2026-10-08. No overall winner is declared.

Project constraints (not web sources): the report is one HTML file with no React, Vite, or Node build; it must work offline when the file is opened or served locally; a view-time API key is a failure; the map colors UFs (states plus DF) and, when useful, about 5,570 municipalities, joined on the IBGE code; a world view is only context; Matplotlib, GeoPandas, and Shapely are forbidden; a small JS library inlined in the HTML is the intended path; hover and a custom light/dark presentation are required; the JS license must allow shipping that JS inside the generated file.

## What do current docs say is the supported way to draw a local GeoJSON choropleth with no basemap tiles for Leaflet, MapLibre GL JS, and Apache ECharts?

### Takeaway

All three can color local polygons from properties and none of them requires a vendor token for that path, but only ECharts documents a tile-free GeoJSON map as the normal setup. Leaflet's choropleth tutorial adds OSM tiles beside the GeoJSON. MapLibre will not render until it has a style document, and its own "local GeoJSON" example still loads a remote basemap style.

### Cited Findings

- Leaflet's choropleth tutorial stores one GeoJSON feature per area, with the numeric value on `properties` (the example uses `properties.density`), then paints with a `style` function that returns `fillColor`, `weight`, `opacity`, `color`, `dashArray`, and `fillOpacity`. In the "Basic States Map" step it also constructs an OSM `TileLayer` (`https://tile.openstreetmap.org/{z}/{x}/{y}.png`) and adds it to the map. The tutorial is a US-states example, not Brazil. — [Leaflet choropleth tutorial](https://leafletjs.com/examples/choropleth/)
- Leaflet map option `layers` defaults to `[]`. `preferCanvas` defaults to `false`, and the reference says that by default all `Path`s are rendered with the SVG renderer; setting `preferCanvas` renders them on a Canvas renderer. `className` on a path is "Only for SVG renderer." — [Leaflet reference](https://leafletjs.com/reference.html)
- Nothing on the Leaflet reference page that was opened says a tile layer is mandatory. The choropleth tutorial's tiles and its GeoJSON layer are separate `addTo(map)` calls. — [Leaflet choropleth tutorial](https://leafletjs.com/examples/choropleth/); [Leaflet reference](https://leafletjs.com/reference.html)
- MapLibre `MapOptions.style` is optional in the type (`StyleSpecification | string`), but the same page says: "When the style is not specified, calling `Map.setStyle` is required to render the map." The value must be a style JSON object or a URL to one. — [MapLibre MapOptions](https://maplibre.org/maplibre-gl-js/docs/API/type-aliases/MapOptions/)
- The MapLibre style-spec root marks `version` as required and equal to 8, and marks `sources` as required. A source does not draw by itself: "Adding a source isn't enough to make data appear on the map because sources don't contain styling details like color or width. Layers refer to a source." `sprite` and `glyphs` are optional. The quickstart examples pass a remote style URL (`https://demotiles.maplibre.org/style.json` or `globe.json`), not an inline empty style. — [MapLibre style spec root](https://maplibre.org/maplibre-style-spec/root/); [MapLibre GL JS introduction](https://www.maplibre.org/maplibre-gl-js/docs/)
- A `geojson` source `data` property "can be a URL or inline GeoJSON." The browser case adds a same-domain or CORS requirement when `data` is a URL. Official `GeoJSONSource` examples include a literal `FeatureCollection` in `addSource`. GeoJSON "is tiled internally for rendering," and "GeoJSON foreign members that cannot be represented by the vector-tile format are not preserved" on rendered features; the docs say to keep that data separately or copy it onto supported feature properties. — [MapLibre style spec, geojson source](https://www.maplibre.org/maplibre-style-spec/sources/); [GeoJSONSource](https://www.maplibre.org/maplibre-gl-js/docs/API/classes/GeoJSONSource/)
- MapLibre's own "View local GeoJSON" example (page metadata `og:created` 2025-06-25, docs crawled 2026-10-06) reads a local file in the browser and calls `addSource({type:'geojson', data})` plus a `fill` layer. The map is still constructed with `style: 'https://tiles.openfreemap.org/styles/bright'`, so the published "local GeoJSON" example is not offline and is not basemap-free. — [View local GeoJSON](https://www.maplibre.org/maplibre-gl-js/docs/examples/view-local-geojson/)
- The documented way to show vectors with no basemap, written for Mapbox GL and using the same style-spec shape, is to replace a streets style URL with an inline object `style: {version: 8, sources: {}, layers: []}`. A second Mapbox snippet puts a single `background` layer in that object and sets `background-color`. The GIS Stack Exchange answer that records the empty style also points readers who want to avoid Mapbox billing at MapLibre. These pages do not show the same snippet on maplibre.org. — [Mapbox, Set a style](https://docs.mapbox.com/mapbox-gl-js/guides/styles/set-a-style/); [GIS Stack Exchange, map with no style](https://gis.stackexchange.com/questions/398348/mapbox-map-with-no-style-only-self-hosted-vector-data)
- A `background` layer needs no source. If it is omitted or transparent, "any part of the map view that does not show another style layer is transparent." — [MapLibre style layers (background)](https://birkskyum.github.io/maplibre-style/layers)
- Data-driven fill colors are ordinary paint expressions. A 2026 Mapbox page that describes MapLibre's GeoJSON path shows `'fill-color': ['case', ['==', ['get', 'contour'], 5], '#1d4ed8', ...]`. The property name in `['get', ...]` is whatever was stored on the feature. — [Use Mapbox APIs in MapLibre GL JS](https://docs.mapbox.com/help/dive-deeper/mapbox-in-maplibre/)
- Apache ECharts' current `registerMap` API accepts a map name plus a GeoJSON object or JSON string (key `geoJSON` or `geoJson`), or the shorter form `registerMap(mapName, geoJSON, specialAreas)`. The official note says `features[i].properties.name` is what ECharts uses "to query the corresponding region, or display the label," that `name` is the default, and that another property can be used via `geo.nameProperty`. `properties.cp` is optional and only affects label placement. The sample GeoJSON in that API page uses arbitrary plane coordinates (`[200, 3000]`), not a tile service. — [ECharts API, registerMap](https://echarts.apache.org/api.html)
- A map series is `type: 'map'` with `map` set to the registered name. `nameProperty` defaults to `'name'` and is "the property name in GeoJSON features used to match with data items." Series data items still carry the join value in their own `name` field even when `nameProperty` points at a different GeoJSON key. `visualMap` maps a number to colors such as `color`. `roam: true` turns on zoom and pan. The Hong Kong editor example is `$.get(geoJson)` then `echarts.registerMap('HK', geoJson)` and a `map` series, with no tile URL. — [ECharts map series (nameProperty default)](https://www.mintlify.com/apache/echarts/charts/map); [ipecharts geo.nameProperty](https://ipecharts.readthedocs.io/en/stable/api/ipecharts.option.geo.html); [ECharts visualMap handbook](https://echarts.apache.org/handbook/en/concepts/visual-map/); [ECharts HK map example](https://echarts.apache.org/examples/en/editor.html?c=map-HK)
- The ipecharts mirror of `option.geo` says a custom projection needs `project` and `unproject`, and shows a Mercator pair. That text was not re-read on echarts.apache.org itself in this pass. The official `registerMap` page tells the reader to see `option.geo` rather than pasting the projection object. — [ipecharts geo projection](https://ipecharts.readthedocs.io/en/stable/api/ipecharts.option.geo.html); [ECharts API, registerMap](https://echarts.apache.org/api.html)
- D3 is not one of the three named libraries, but it is the other self-contained choropleth path in the assigned pain points. `d3.geoMercator`, `d3.geoConicEqualArea` (Albers' conic equal-area), and `d3.geoConicEquidistant` are all provided by `d3-geo`, which the extended-projection repo says is already in the default D3 bundle. A choropleth is `d3.geoPath().projection(...)` on GeoJSON features, with `fill` set from a joined value. There is no style JSON and no tile layer in that model. — [d3-geo-projection API (which projections live in d3-geo)](https://github.com/d3/d3-geo-projection); [D3 graph gallery choropleth hover](https://d3-graph-gallery.com/graph/choropleth_hover_effect.html)

### Inferences

- Leaflet passes "local GeoJSON choropleth, no token." It passes "no basemap tiles" only if the generator does not copy the tutorial's `TileLayer`. The docs allow a map with no layers; they do not ship a tile-free choropleth example.
- MapLibre passes "inline GeoJSON, no token" and fails "no style document." A tile-free map is an inline style with a `background` layer plus a `fill` layer, which is documented on the shared style spec and on Mapbox's empty-style page, not as a MapLibre choropleth tutorial. The join key has to be a normal feature property; a GeoJSON foreign member will not survive internal tiling.
- ECharts passes "local GeoJSON, no tiles, no token" with the fewest extra concepts of the three: `registerMap` plus a `map` series plus `visualMap`. For an IBGE code that is not stored in `properties.name`, the docs require `nameProperty`, and the data item is still matched through `name`. Default drawing fits the GeoJSON into the chart; a geographic projection is a separate `project`/`unproject` pair, not the default.
- None of the three official choropleth or GeoJSON pages opened here uses a Brazilian UF or municipality mesh, and none mentions an IBGE code.

### Gaps

- The style-spec root fetch was cut before the `layers` property's required/optional line. `version` and `sources` were visible as required. The claim that an empty style must include `layers: []` comes from the Mapbox empty-style example and the GIS Stack Exchange answer, not from a MapLibre sentence that says `layers` is required.
- `option.geo.projection` was not opened on echarts.apache.org. The Mercator `project`/`unproject` snippet is from the ipecharts mirror.
- No official Leaflet, MapLibre, or ECharts page found in this pass names a Brazilian municipality property (`CD_MUN`, `codarea`, or similar) as the join key.

## What published evidence exists on frame rate or "too many polygons" for Brazilian municipalities in Leaflet versus Canvas/WebGL libraries?

### Takeaway

No source found in this pass reports a frame rate, hover latency, or "too many polygons" result for the about 5,570 Brazilian municipalities. The nearest measurements disagree: a 2025 four-library study has Leaflet faster than MapLibre up through 10,000 polygons, while a 2024 write-up of roughly 200,000 complex polygons has Leaflet taking about 20 seconds. Vertex count and file size show up as separate bottlenecks from feature count.

### Cited Findings

- A 2025 ISPRS International Journal of Geo-Information paper compared Leaflet, OpenLayers, Mapbox GL JS, and MapLibre GL JS on points, lines, and polygons. "Regardless of feature types, Leaflet and OpenLayers excelled for features up to 10,000." "For up to 50,000 lines and 10,000 polygons, Leaflet and OpenLayers were the fastest in all scenarios." At 50,000 polygons the reported averages are Mapbox GL JS 1265 ms (SD 28.13 ms), OpenLayers 1366.4 ms (SD 11.42 ms), and Leaflet 1539.9 ms (SD 25.68 ms). "MapLibre GL JS was significantly slower than all other libraries for both lines and polygons across all scenarios." The same paper says Leaflet and OpenLayers get slower as feature counts rise, whereas for Mapbox and MapLibre "any performance impact is offset to 1000 features and beyond." The conference abstract repeats the 10,000-polygon and 50,000-polygon figures. The features are generated test sets, not Brazilian municipalities, and the numbers are initial render times, not hover frame rates. — [IJGI 2025, Vector Data Rendering Performance](https://www.mdpi.com/2220-9964/14/9/336); [ICA abstract of the same study](https://ica-abs.copernicus.org/articles/10/14/2025/ica-abs-10-14-2025.pdf)
- A May 2024 Medium article on San Francisco city lots (the GeoJSON linked from the article is the public `citylots.json` dataset) says Leaflet "took an average of 20 seconds (with a Standard Deviation of 2 seconds for 5 reloads) to render GeoJSON," used 100% CPU while rendering, and that Chrome was using 4 GB afterward. The author describes MapLibre as the faster WebGL path and says Leaflet "also has Canvas support," but the excerpts retrieved do not give a MapLibre time or an FPS. The article frames the dataset as hundreds of thousands of polygons, not 5,570. — [Rendering Hundreds of Thousands of Polygons using JS](https://medium.com/@dipakpatil2615/rendering-hundreds-of-thousands-of-polygons-using-js-because-gis-deserves-modern-visualization-e27d678dccca)
- On GIS Stack Exchange, a large multi-feature shapefile is reported to freeze the Leaflet UI, and the accepted suggestion is `preferCanvas: true`, plus plugins. A follow-up comment says a 50 MB polygon layer that froze on zoom and pan became usable after `preferCanvas: true`. A second answer says Leaflet.VectorGrid "render[ed] 100,000 5 point polygons without issue" and that the data has to be GeoJSON or TopoJSON tiles, not one GeoJSON overlay. — [Leaflet freezes on a large shapefile](https://gis.stackexchange.com/questions/357530/map-on-leaflet-freezes-if-load-shapefile-data-with-large-size)
- Leaflet's own reference does not give a polygon budget. It only documents the switch: default SVG for every `Path`, or Canvas when `preferCanvas` is true. `className` styling exists only on the SVG renderer. — [Leaflet reference](https://leafletjs.com/reference.html)
- Leaflet 2.0.0-alpha.1 has an open-at-the-time report (2026-01-07, milestone 2.0.0-alpha.2) that with `preferCanvas: true` a vector disappears after pan, zoom, or `fitBounds`. That report is about the alpha, not the 1.x reference page above. — [Leaflet issue #10061](https://github.com/Leaflet/Leaflet/issues/10061)
- MapTiler publishes a Leaflet example titled "Display thousands of polygons in Leaflet" whose method is the `leaflet-maptilersdk` plugin, not Leaflet's SVG or Canvas renderer. The page says to replace `YOUR_MAPTILER_API_KEY_HERE`. That is evidence that a vendor considers "thousands of polygons" a reason to leave vanilla Leaflet, and it fails the no-token test. — [MapTiler, display thousands of polygons in Leaflet](https://docs.maptiler.com/leaflet/examples/helpers-polygon/)
- A MapLibre project skill, not a timed benchmark, says GeoJSON needs no tile server under about 5,000 features when click or hover is required, and that 5,000 to 100,000 features can stay as GeoJSON "if you can simplify and accept 1–3s load delay." About 5,570 municipalities sits on that boundary. The page does not mention Brazil. — [MapLibre tile-sources skill](https://raw.githubusercontent.com/maplibre/maplibre-agent-skills/main/skills/maplibre-tile-sources/SKILL.md)
- `GeoJSONSource` documents that GeoJSON is converted to vector tiles inside the library, which is the mechanism behind zooming a large polygon set without one SVG node per municipality. — [GeoJSONSource](https://www.maplibre.org/maplibre-gl-js/docs/API/classes/GeoJSONSource/)
- A July 2026 note on Leaflet plus PostGIS says that 811 Nigerian admin polygons at full resolution were a 16 MB payload and took about 3 minutes to show on a 500 kb/s link; simplifying to a 1 MB geometry cut that to about 20 seconds. The bottleneck described is coordinate density and download size, not a renderer FPS. It is not a Brazil study, and it is one engineering note. — [Squeezing performance out of maps with lots of polygons](https://www.standardco.de/notes/squeezing-performance-out-maps-with-lots-of-polygons-leaflet-postgis)
- Brazilian examples that name a library and a mesh, but do not publish timings: an Observable notebook draws Brazilian regions from TopoJSON with `d3.geoMercator().fitSize`, and a second cell says a GeoJSON of the same subject did not work with `geoMercator` but did work with `geoIdentity` (consistent with projected coordinates rather than lon/lat, not with Mercator being unable to draw Brazil). A gist compares Brazilian states in `geoConicEqualArea` with `parallels([-2, -22])`, `rotate([54, 0])`, against `geoMercator`, and points at an Albers equal-area Brazil SIRGAS 2000 definition; that gist does not use `geoConicEquidistant` and does not report error numbers in the excerpt retrieved. A GitHub repo describes an HTML choropleth of Brazilian counties with D3; its projection and join field were not opened. — [Observable, Brazil map visualizations](https://observablehq.com/@giorgi-ghviniashvili/brazil-map-visualizations); [gist, Brazilian states Albers vs Mercator](https://gist.github.com/ppKrauss/e6c12bf84e732ca4cbf0694808619cad); [choropleth_br_counties](https://github.com/luimucar/choropleth_br_counties)
- No ECharts page opened here times a map series at municipality scale. The documented interaction for a registered GeoJSON map is `roam` on the `map` series (zoom and pan) and `tooltip.trigger: 'item'`. — [ECharts map series](https://www.mintlify.com/apache/echarts/charts/map); [ECharts HK example](https://echarts.apache.org/examples/en/editor.html?c=map-HK)

### Inferences

- Leaflet at municipality scale does not fail on published numbers for 5,570 features. The 2025 study puts 10,000 polygons inside the range where Leaflet's initial render beat MapLibre. It can still fail in practice when each municipality is a heavy ring: the SF-lots write-up and the 50 MB shapefile report are the warnings, and both are well above a 27-UF map. `preferCanvas: true` is the documented mitigation and keeps the same GeoJSON API; it drops per-path SVG classes. VectorGrid is a different architecture (tiles), so it is more moving parts, not a drop-in.
- MapLibre's advantage is not established at 5,570 simple polygons. It is established as the architecture aimed at larger, tiled GeoJSON, and as the library that did better in the 200,000-polygon anecdote. The 2025 paper is a direct contradiction if someone claims WebGL is always faster at this size.
- ECharts and D3 have no published municipality-scale frame rate in the sources found. D3's Brazil examples are SVG path choropleths, so they share the "one DOM path per area" cost with Leaflet's default renderer. ECharts map series is a canvas chart with built-in roam, but that is a mechanism claim, not a timing.
- For a UF-only map (27 areas plus DF), none of the performance sources suggests a problem for any of these libraries.

### Gaps

- No frame rate, hover-pick time, or memory figure was found for a Brazilian municipal mesh in Leaflet, Canvas Leaflet, MapLibre, ECharts, or D3.
- The Medium article's MapLibre timing was not in the retrieved text, so it cannot be quoted.
- The Albers-vs-Mercator gist was not opened far enough to quote a measured area or shape error, and spatialreference.org was not opened to verify the SIRGAS 2000 parallel values independently of the gist.
- `geoConicEquidistant` is in `d3-geo`, but no 2024–2026 Brazil choropleth found here uses it or compares it with `geoConicEqualArea` or `geoMercator`.
- ECharts' renderer for the map series (canvas versus SVG) was not confirmed from an apache.org sentence in this pass.

## Which approach needs the fewest moving parts for a Python script that writes one HTML file?

### Takeaway

For a script that only concatenates strings into one HTML file, D3 and ECharts are one script plus inline GeoJSON and no style document. Leaflet adds a CSS file and a map div with a height, and the author must remember to omit tiles. MapLibre adds a style object, a source, a layer, a WebGL worker, and, in v6, an ES module. Highcharts is compact but fails the share test in the next section. This is an inference from the APIs, not a published ranking.

### Cited Findings

- D3's license file permits use, copy, modification, and distribution provided the copyright notice and permission notice appear in all copies. A choropleth needs a projection, `geoPath`, and a DOM or SVG mouse handler written by the page. There is no CSS bundle and no worker in the gallery example. — [D3 LICENSE](https://raw.githubusercontent.com/d3/d3/main/LICENSE); [D3 choropleth hover](https://d3-graph-gallery.com/graph/choropleth_hover_effect.html)
- ECharts `registerMap` takes the GeoJSON object inline. The HK example is one `registerMap` call and one `setOption` with `type: 'map'`, `roam: true`, and a tooltip. Color is a `visualMap`, not a second library. The distribution terms are Apache-2.0: copies may be distributed if the license is included and the required notices are kept. — [ECharts API, registerMap](https://echarts.apache.org/api.html); [ECharts HK example](https://echarts.apache.org/examples/en/editor.html?c=map-HK); [ECharts LICENSE](https://raw.githubusercontent.com/apache/echarts/master/LICENSE)
- Leaflet's tutorial is one `L.map`, an optional tile layer, and one GeoJSON layer with `style` and, in the full tutorial pattern, per-feature mouse handlers. The library is distributed as JS plus CSS. BSD-2-Clause allows source or binary redistribution if the copyright notice, conditions, and disclaimer are kept. The copyright line on `main` reads 2010–2026, Volodymyr Agafonkin. — [Leaflet choropleth tutorial](https://leafletjs.com/examples/choropleth/); [Leaflet LICENSE](https://raw.githubusercontent.com/Leaflet/Leaflet/main/LICENSE)
- MapLibre's quickstart is a CSS link, a module script, and a `Map` whose `style` is a URL. v6 dropped the UMD builds (`maplibre-gl.js`); a page that used `<script src>` must switch to `<script type="module">`. The worker URL is auto-detected from `import.meta.url` and, for a cross-origin CDN, loaded through a same-origin blob URL. CSP needs `worker-src` permission for `blob:` when the script is cross-origin. The implementation returns an empty default worker URL when the module URL is not `http:` or `https:`. — [MapLibre introduction](https://www.maplibre.org/maplibre-gl-js/docs/); [v5 to v6 migration](https://www.maplibre.org/maplibre-gl-js/docs/guides/v5-to-v6-migration-guide/); [web_worker.ts defaultWorkerUrl](https://github.com/maplibre/maplibre-gl-js/blob/main/src/util/web_worker.ts)
- A September 2026 MapLibre discussion titled "Help bundling v6 for local use (double-click & open)? (worker issue)" says the `file://` origin is the problem: v6's ESM worker is not started from an opaque `file://` page. A commenter reports that Chromium treats a blob worker URL as cross-origin on `file://` (`location.origin` is `file://`, the blob origin is `null`) and that a classic worker was started only by appending `#maplibre-gl-worker.cjs` to the blob URL. That is a discussion workaround, not an official supported `file://` mode. — [MapLibre discussion #8225](https://github.com/maplibre/maplibre-gl-js/discussions/8225)
- MapLibre's license is BSD-3-Clause (copyright 2023, MapLibre contributors), and the file also carries BSD-3-Clause for included mapbox-gl-js v1.13 and earlier. Redistribution in source or binary is allowed if the notices are kept; the name may not be used to endorse a product without permission. — [MapLibre LICENSE.txt](https://raw.githubusercontent.com/maplibre/maplibre-gl-js/main/LICENSE.txt)
- Hover that is good enough for a presentation is built in for ECharts (`tooltip.trigger: 'item'`) and is a documented GeoJSON pattern for Leaflet (style plus per-feature events in the choropleth tutorial). MapLibre hover is `queryRenderedFeatures` or feature-state on top of the layer the page added; the local-GeoJSON example retrieved shows the layer, not a hover popup. D3 hover in the gallery is two hand-written handlers that change opacity and stroke. — [ECharts map series](https://www.mintlify.com/apache/echarts/charts/map); [Leaflet choropleth tutorial](https://leafletjs.com/examples/choropleth/); [View local GeoJSON](https://www.maplibre.org/maplibre-gl-js/docs/examples/view-local-geojson/); [D3 choropleth hover](https://d3-graph-gallery.com/graph/choropleth_hover_effect.html)

### Inferences

- Fewest library concepts, if the Python script is willing to emit a projection and the mouse handlers: D3. One inlined script, one inlined GeoJSON, SVG fills, no CSS framework, no worker, no style JSON. ISC allows shipping it if the notice is in the file.
- Fewest cartographic concepts, with hover and zoom already in the option object: ECharts. The script writes `registerMap('brasil', <geojson>)` and a `map` series whose data `name` equals the IBGE code (`nameProperty` set to that field). Apache-2.0 allows shipping it if the license text ships with it. A geographic look (Mercator or a Brazil conic) is extra code that D3 would also need; skipping it means the chart stretches lon/lat into the div.
- Leaflet is still a small embed, and it is the only one of the four whose tutorial is literally a choropleth, but a correct offline file must delete the OSM tiles the tutorial adds, set a div height, and inline both JS and CSS. Default SVG is the wrong renderer to copy blindly for 5,570 polygons; `preferCanvas` is one extra option, not a new library.
- MapLibre has the most moving parts that a single HTML file can get wrong: style JSON even when there are no tiles, a `geojson` source, a `fill` layer, paint expressions for the party colors, CSS for popups, an ES-module worker, and a `file://` failure mode documented in 2026. It passes a locally served file more easily than a double-clicked file. It does not win "fewest moving parts."
- Styling against a custom light/dark page, rather than a streets basemap: D3, ECharts, and a tile-free Leaflet map pass, because fill color is page-owned. MapLibre passes only when the style is a solid `background` plus the choropleth; the official examples fail this by loading Bright or demo tiles.

### Gaps

- Bundle sizes (minified kilobytes of leaflet.js, echarts.min.js, maplibre-gl, d3) were not measured in this pass, so "fewest moving parts" is about concepts and failure modes, not download weight.
- Whether ECharts' full build can be reduced to the map series plus canvas renderer without a bundler was not checked. A bundler would violate the project constraint. The safe statement is that the prebuilt full script is what a no-build HTML file would inline.
- No source ranks these four for "Python prints one HTML file."

## Which popular options fail the free/share or offline test (Google Maps, Mapbox GL with a token, Highcharts Maps non-commercial clause, MapTiler/Stadia tiles)?

### Takeaway

Google Maps JavaScript API, current Mapbox GL JS, MapTiler-hosted tiles, and Stadia-hosted tiles fail offline or no-token use. Highcharts fails the free redistribution test: the non-commercial EULA in force in 2026 forbids giving the software to a third party, and the company says internal business use needs a paid license. Leaflet (BSD-2), MapLibre (BSD-3), ECharts (Apache-2.0), and D3 (ISC) allow shipping the JS if their notices are kept. Those four licenses do not license the municipality mesh.

### Cited Findings

- Google's Maps JavaScript API error-message page, updated 2026-10-07, says billing must be enabled and "all requests must include a valid API key." The loader shown is `https://maps.googleapis.com/maps/api/js?key=YOUR_API_KEY`. A missing key is the `NoApiKeys` warning. That fails both "no token at view time" and "open the file offline." — [Maps JavaScript API error messages](https://developers.google.com/maps/documentation/javascript/error-messages)
- Mapbox GL JS v2 and later is not the old BSD license. The v2.0 merge note (2020-12-08) says v2 is governed by the Mapbox Terms of Service, the license "terminates automatically if a user no longer has an active Mapbox account," and the FAQ answer to "Can I still use self-hosted map tiles?" is "Developers simply need a Mapbox account and access token to use this v2." The same note says a billable map load happens when a `Map` is initialized. ### Inferences

- Fail the free/share or offline test, as documented: Google Maps JavaScript API; Mapbox GL JS v2+ even if the polygons are local, because the current library asks for an account token and the vendor defined a map load as billable; any report whose basemap is MapTiler, Stadia, OpenFreeMap, or CARTO tiles; Highcharts under the non-commercial EULA, because shipping the JS inside an HTML file that other people open is distribution, which that EULA forbids. A paid Highcharts license might change the last point, but the agreement text found here does not grant a general right to redistribute the library inside generated files.
- Pass the JS-license-and-no-token test: Leaflet, MapLibre, ECharts, and D3, provided the HTML contains the required notice and does not call a tile host. MapLibre still has the separate `file://` worker risk in the previous section; that is an offline-mechanics failure mode, not a license failure.
- Pass a custom light/dark look only when no streets tiles are drawn. Loading the documented MapTiler, Stadia, Mapbox Standard, or OSM layers fails that presentation test even before the token test.
- The mesh is a separate license. Natural Earth is public domain in Highcharts' own map-collection write-up; an IBGE municipal GeoJSON is not covered by any of the JS licenses above.

### Gaps

- The full Highcharts commercial price list and every paid grant were not read. Only EULA 1.0, the education/personal FAQ, the April 2026 clarification, map-collection LICENSE.md, and slices of Standard License Agreement 19.1 were opened.
- Whether Mapbox GL JS v2 still refuses to construct a `Map` when `accessToken` is unset and the style is a fully inline GeoJSON style was not re-tested in a browser. The 2020 issue FAQ and the 2026 getting-started page are the sources used here; a 2019 third-party note that v1 could run without a token is about the BSD generation and was not treated as current.
- Stadia's behavior on `file://` specifically was not tested; the docs simply do not list it as an unauthenticated origin, and tiles would still require the network.
- No source in this pass states the license of the IBGE municipal mesh. That belongs with the boundary-file research, not with the JS library license.
