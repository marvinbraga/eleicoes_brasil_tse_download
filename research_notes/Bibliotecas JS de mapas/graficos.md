# JS chart libraries with map charts (free/share fact sheet)

Research date: 2026-10-08. "Free/share" here means: use the library and redistribute it inside generated HTML, with no fee and no non-commercial-only clause. Facts below are from the pages fetched that day. Conflicting pages are both cited. This note does not pick a library.

Libraries checked: Apache ECharts 6.1.0, echarts-countries-js, Plotly.js 4.1.2, Highcharts / Highcharts Maps 13.1.1, amCharts 5.21.0, ApexCharts plus the separate ApexMaps product, chartjs-chart-geo 4.3.6, billboard.js 4.1.1, Observable Plot 0.6.17.

## Which of these can color Brazilian municipalities from an external GeoJSON with no account and no API token?

### Takeaway
ECharts, Plotly.js SVG `choropleth`, Highcharts Maps, amCharts 5, ApexMaps, chartjs-chart-geo, and Observable Plot can all take an external GeoJSON (so an IBGE municipality file) without an account or a map API token. billboard.js cannot: it has no geo chart. None of the bundled Brazil maps found are municipality-level; the municipality file has to be yours. Plotly's SVG choropleth path has open bug reports when `geojson` is set.

### Cited Findings
- Apache ECharts does not ship map polygons. The current API registers a named map from GeoJSON or from SVG, then a `map` series or `geo` component refers to that name. The docs show `echarts.registerMap('my_geo_sample', {geoJSON: geoJSONSample})` and `echarts.registerMap('iceland', geoJSON)` fed by `$.get` of a GeoJSON URL. No account or token appears in that API. — [ECharts API, registerMap, page dated 2026-09-01](https://echarts.apache.org/api.html); [echarts-examples README, Iceland GeoJSON fetch](https://github.com/apache/echarts-examples); [v4 download-map page: "ECharts doesn't come with Map data"](https://echarts.apache.org/en/download-map.html)
- From ECharts v5.3.0, a tree-shaken build cannot call `registerMap` until `MapChart` or `GeoComponent` has been imported. The full `echarts` script build is not that case. — [ECharts API](https://echarts.apache.org/api.html)
- echarts-countries-js is an unofficial asset pack (the README says it is not an Apache ECharts project). It is a script you add beside ECharts, not a requirement for your own GeoJSON. It lists Brazil among 213 countries. Polygon level inside `Brazil.js` was not opened. — [echarts-maps/echarts-countries-js](https://github.com/echarts-maps/echarts-countries-js); [npm echarts-countries-js 1.0.5](https://www.npmjs.com/package/echarts-countries-js)
- Plotly.js `choropleth` colors a built-in world (country names or ISO-3) or `USA-states`, or a GeoJSON you pass. The Python docs, which describe the same trace, say geometry is either "a supplied GeoJSON file" or "built-in geometries within plotly: US states and world countries", joined with `featureidkey` (example `properties.district`). The JS docs' world and US examples use no token. — [Plotly.js choropleth](https://plotly.com/javascript/choropleth-maps/); [plotly.py choropleth-maps.md](https://github.com/plotly/plotly.py/blob/main/doc/python/choropleth-maps.md); [PR that added `geojson`, `featureidkey`, and `locationmode: 'geojson-id'`](https://github.com/plotly/plotly.js/pull/4419)
- Plotly issue #7724, opened 2026-03-05 and still open in the fetched issue page, says a custom-GeoJSON `choropleth` with `locationmode: 'geojson-id'` drew a broken SVG, while the same data on `choroplethmap` drew correctly. Issue #6767, opened 2023-10-31 and still labeled open, says setting `geojson` to your own URL still loads a GeoJSON from `cdn.plot.ly` first. That is not an API token, but it is a network call to Plotly's CDN. — [issue #7724](https://github.com/plotly/plotly.js/issues/7724); [issue #6767](https://github.com/plotly/plotly.js/issues/6767)
- The Plotly.js Florida example on the choropleth page uses `type: 'scattermap'` and `map.style: 'light'` with GeoJSON layers and shows no access token in the snippet. This note did not re-test whether that style still needs a Mapbox token in 4.1.2. The SVG `choropleth` / `plotly.js-geo` bundle does not use that tile trace. — [Plotly.js choropleth page](https://plotly.com/javascript/choropleth-maps/); [dist README: geo bundle is `choropleth`, `scatter`, `scattergeo`](https://github.com/plotly/plotly.js/blob/main/dist/README.md)
- Highcharts Maps loads GeoJSON and TopoJSON natively. The custom-GeoJSON article says a file exported from QGIS "can be used directly with Highcharts Maps" and links a boilerplate that pastes GeoJSON into `Highcharts.mapChart`. The Brazil demo fetches `br-all.topo.json` with no key. No account is required to download the library. — [Custom GeoJSON maps](https://www.highcharts.com/docs/maps/custom-geojson-maps); [Map collection](https://www.highcharts.com/docs/maps/map-collection); [Brazil br-all JSFiddle](https://jsfiddle.net/gh/get/jquery/1.11.0/highslide-software/highcharts.com/tree/master/samples/mapdata/countries/br/br-all)
- amCharts 5 MapChart takes GeoJSON on `MapPolygonSeries` (`geoJSON: am5geodata_worldLow` in the tutorial; the same option is how any GeoJSON object is passed). The product page says "No tile server, no API key, no per-load fees." — [Map chart tutorial](https://www.amcharts.com/docs/v5/charts/map-chart/); [amCharts Maps product page](https://www.amcharts.com/javascript-maps/)
- ApexMaps is a separate library from ApexCharts core, introduced in a post dated 2026-07-30. `geo.map` accepts a registry id, a URL, or a GeoJSON/TopoJSON object. `ApexMaps.registerMap(id, geometry, meta)` takes a GeoJSON `FeatureCollection`. The extending page says registering your own geometry is a free Community feature. No token is shown. Choropleth is in the "free, always" column; a license key is for other features (cluster, hexbin, custom projection, drilldown). — [Introducing ApexMaps](https://apexcharts.com/blog/introducing-apexmaps/); [Installation](https://apexcharts.com/apexmaps/docs/installation-usage/); [Configuration: `geo.map`](https://apexcharts.com/apexmaps/docs/configuration-overview/); [Extending / registerMap](https://apexcharts.com/apexmaps/docs/extending/); [ApexMaps licensing](https://apexcharts.com/apexmaps/docs/licensing/)
- chartjs-chart-geo adds Chart.js types `choropleth` and `bubbleMap`. Its getting-started page says the plugin "is not providing the geometric data files" and that each point needs a `.feature` (GeoJSON feature) plus a `.value`. No token is described. — [Getting started](https://www.sgratzl.com/chartjs-chart-geo/getting-started.html); [package.json license and UMD paths](https://github.com/sgratzl/chartjs-chart-geo/blob/main/package.json)
- Observable Plot's `Plot.geo(data, options)` takes a GeoJSON object, a feature collection, or an array of features, and reads a field such as `fill: "unemployment"` from `properties`. The docs show a counties choropleth. No basemap account is described. The getting-started page shows a static HTML file loading Plot from jsDelivr. — [Geo mark](https://observablehq.com/plot/marks/geo); [Getting started, vanilla HTML](https://observablehq.com/plot/getting-started)
- billboard.js 4.1.1 (2026-09-30) is an active D3-based chart library (MIT) and does not publish a map or choropleth type. The type lists found are cartesian, arc, radar, treemap, candlestick, and similar. No D3 wrapper that still ships a Brazil polygon file was identified in this pass. `br-atlas` is TopoJSON data for D3, not a chart library. — [billboard.js 4.1.1 release](https://newreleases.io/project/github/naver/billboard.js/release/4.1.1); [README, MIT and supported types](https://github.com/naver/billboard.js); [site listing 20 chart types, no map](https://naver.github.io/billboard.js/); [br-atlas](https://github.com/mtrovo/br-atlas)

### Inferences
- For an IBGE municipality GeoJSON, the practical no-token path is: fetch the file yourself and hand it to ECharts `registerMap`, Plotly `choropleth.geojson`, Highcharts `chart.map` / `series.mapData`, amCharts `MapPolygonSeries.geoJSON`, ApexMaps `registerMap` or `geo.map`, chartjs-chart-geo point `.feature`, or `Plot.geo`. The join key (`properties` name, `hc-key`, `featureidkey`, feature id) is your mapping; none of these libraries know IBGE codes unless the file or your data uses them.
- "Can" for Plotly SVG choropleth is what the API documents. The 2026 bug report means that path is not something to treat as proven for a large custom polygon set until it is tried. `choroplethmap` is a different trace and lives in the `map` bundle, not the `geo` bundle.
- Highcharts and ApexMaps are technically able to draw the file with no token. Whether you may ship that HTML for a government or campaign report is a license question, answered in the next section. amCharts can do it with no token, but the free license keeps a logo.

### Gaps
- `Brazil.js` inside echarts-countries-js was not opened, so its feature count is unknown.
- Whether Plotly 4.1.2 `scattermap` / `choroplethmap` with `style: 'light'` still requests a Mapbox token was not re-tested. Only the absence of a token in the published snippet was recorded.
- ApexMaps script-tag (non-module) distribution was not confirmed. The installation page that was fetched shows an ES module import.
- No maintained D3 wrapper that bundles a Brazil map was found. The search was not exhaustive of every D3 plugin.

## Which licenses forbid redistribution or require payment when the HTML is used inside a government or campaign election report?

### Takeaway
Apache-2.0, MIT, and ISC libraries (ECharts, Plotly.js, chartjs-chart-geo, Observable Plot, billboard.js) do not have a non-commercial clause. Highcharts free terms are personal and educational only, so a government or campaign report needs a paid license, and the free terms also restrict distributing the software and require a watermark. amCharts' own LICENSE file allows commercial bundling if the logo stays; a marketing `llms.txt` on the same site says the opposite. ApexCharts / ApexMaps are free only under a 2 million USD revenue, budget, or funding line; at or above that line they are paid, including for a public body whose operating budget crosses the line.

### Inferences
- Against the free/share definition (redistribute inside generated HTML, no fee, no non-commercial-only clause): ECharts, Plotly.js, chartjs-chart-geo, and Observable Plot qualify on the license texts found. billboard.js qualifies on license and fails on capability.
- Highcharts does not qualify. A government election report is not "personal enjoyment or self-education" and is not coursework. The shop tells non-US governments to use the paid standard agreement. Putting `highmaps.js` inside HTML that you hand to other people also collides with the education/personal rule against "distribution of the Software outside of servers owned or operated by Licensee." The free visual still has to keep the watermark.
- amCharts' package LICENSE does allow a government or campaign page, including commercial, if the logo and the LICENSE file stay and you are not selling amCharts itself. Removing the logo is the paid step. `llms.txt` says commercial use needs a paid license. Do not treat those two as the same rule; the file inside the package is the grant that was fetched in full.
- ApexCharts / ApexMaps do not qualify as unconditional free/share. A body at or above 2 million USD of revenue, operating budget, or funding must pay. Whether a given campaign is under that line is a fact about the organization, not about the library. Notices must travel with the files. OEM is the plan aimed at redistributing inside a product you sell; a static report is closer to "deploy applications," which the Community text allows only while the organization stays under the line.
- echarts-countries-js should not be treated as free/share-clean until the ISC versus ODbL conflict is resolved. If ODbL applies, share-alike attaches to the database, which is a redistribution condition even though commercial use is allowed.

### Gaps
- The full Apache-2.0 and MIT license bodies were not re-copied in this pass. The claim is the SPDX id and the publishers' statements, not a line-by-line audit of those licenses.
- Chart.js's own LICENSE file was not opened.
- Observable Plot's LICENSE file was not opened; ISC is from Best of JS and Snyk, and the two disagree on the 0.6.17 publish date (Snyk version table says 02/2025; the same Snyk page also says "published 10 months ago").
- No Highcharts page was found that uses the words "election" or "political campaign." The conclusion for a campaign is the general personal/educational limit, not a campaign-specific clause.
- amCharts commercial-license price and the exact logo behavior in 5.21.0 were not re-checked beyond the download page and the 5.1.5 LICENSE file.
- Whether ApexMaps' Community grant treats a public election agency's budget as "operating budget" is the wording of the license ("operating budget, funding, or equivalent financial resources"). This note did not ask ApexCharts for a ruling.

## What is the Brazil map resolution they bundle (states only, or municipalities)?

### Takeaway
No library in this set was found shipping Brazilian municipalities. Highcharts and amCharts ship Brazil at state level (27 units in the Highcharts demo). ApexMaps documents Brazil as admin-1. ECharts, Plotly, chartjs-chart-geo, and Observable Plot do not bundle a Brazil polygon layer. World maps in Plotly, amCharts, Highcharts, and ApexMaps are countries, not Brazilian municipalities.

### Cited Findings
- ECharts: "ECharts doesn't come with Map data" on the download-map page. Current `registerMap` expects you to supply GeoJSON. There is no official Brazil file in the library tarball described by the docs. — [download-map](https://echarts.apache.org/en/download-map.html); [API](https://echarts.apache.org/api.html)
- echarts-countries-js lists "巴西 (Brazil)" as one of 213 country scripts. Whether that file is an outline, states, or municipalities was not verified by opening it. npm release 1.0.5 is from 2022-02-13. — [npm readme country list](https://www.npmjs.com/package/echarts-countries-js)
- Plotly built-in choropleth geometries are world countries and US states. There is no Brazil-states or Brazil-municipalities location mode in the docs that were fetched. A world choropleth can color the country Brazil as one polygon (`iso-3` / country name). — [plotly.py choropleth-maps.md](https://github.com/plotly/plotly.py/blob/main/doc/python/choropleth-maps.md); [Plotly.js examples: country names, ISO codes, USA-states](https://plotly.com/javascript/choropleth-maps/)
- Highcharts Map Collection version listed on the index page is 2.3.2. The Brazil demo loads `countries/br/br-all.topo.json` and joins keys `br-sp`, `br-ma`, `br-pa`, `br-sc`, `br-ba`, `br-ap`, `br-ms`, `br-mg`, `br-go`, `br-rs`, `br-to`, `br-pi`, `br-al`, `br-pb`, `br-ce`, `br-se`, `br-rr`, `br-pe`, `br-pr`, `br-es`, `br-rj`, `br-rn`, `br-am`, `br-mt`, `br-df`, `br-ac`, `br-ro`. That is 27 units: the states plus the Federal District. The collection docs define admin1 as the first subdivision (states) and say Admin2 "we have only compiled selected countries." Brazil is not named among those. World maps in the same collection are countries (Natural Earth). — [map collection index](https://code.highcharts.com/mapdata/); [map collection docs](https://www.highcharts.com/docs/maps/map-collection); [Brazil demo data](https://jsfiddle.net/gh/get/jquery/1.11.0/highslide-software/highcharts.com/tree/master/samples/mapdata/countries/br/br-all)
- amCharts geodata 5.1.6 is the version named on the download page (2026-07-27). The unpkg file list for 5.1.5 contains `brazilHigh.json` (106 kB) and `brazilLow.json` (46 kB). The same listing has `colombiaMuniHigh.json` / `colombiaMuniLow.json` and does not show a `brazilMuni*` file in the portion fetched. Second-level "county" directories documented for v5 are Canada, Mexico, and the United States, not Brazil. Country maps are named like `franceLow` versus a separate `franceDepartmentsLow`, so `brazilLow` / `brazilHigh` are the country subdivision maps, not a second file of municipalities. World maps are `worldLow`, `worldHigh`, `worldUltra`. — [Download page, geodata 5.1.6](https://www.amcharts.com/download/); [unpkg json directory @5.1.5](https://app.unpkg.com/@amcharts/amcharts5-geodata@5.1.5/files/json); [regional maps tutorial](https://www.amcharts.com/docs/v5/tutorials/using-regional-maps/); [country-data docs, France departments as a separate map](https://www.amcharts.com/docs/v5/charts/map-chart/country-data/)
- ApexMaps README: "26 boundary packs cover world countries and coastline... and admin-1 for China, India, Japan, Germany, the UK, France, Italy, Canada, Brazil, Russia, Mexico, Australia, South Korea, Spain and Indonesia." Admin-1 is states, not municipalities. The license page says Natural Earth admin-1 "for 15 countries." World pack id example: `world/countries@110m`. — [apexmaps README](https://github.com/apexcharts/apexmaps); [licensing geometry table](https://apexcharts.com/apexmaps/docs/licensing/)
- chartjs-chart-geo and Observable Plot ship no boundary files. TopoJSON client code inside chartjs-chart-geo converts topology; it is not a Brazil map. — [getting started warning](https://www.sgratzl.com/chartjs-chart-geo/getting-started.html); [Plot.geo docs](https://observablehq.com/plot/marks/geo)
- billboard.js ships no geographic boundaries. — [project site](https://naver.github.io/billboard.js/)

### Inferences
- "States only" is directly evidenced for Highcharts `br-all` (the 27 `hc-key`s) and for ApexMaps (the word admin-1). For amCharts it is inferred from file names, file size, and the absence of a Brazil entry in the second-level directory docs, not from a feature count inside `brazilLow.json`.
- A world choropleth in any of these libraries colors Brazil as one country. It does not color municipalities.
- IBGE municipalities (about 5,570 units) have to be loaded as your own GeoJSON or TopoJSON. `br-atlas` is an example of that kind of file for D3, derived from IBGE, not a product of these chart vendors. — [br-atlas](https://github.com/mtrovo/br-atlas)

### Gaps
- The Highcharts map index was not fully listed, so a Brazil admin2 file could exist without being linked from the `br-all` demo. The collection text says Admin2 covers only selected countries and the Brazil demo that was fetched is the 27-unit map.
- `brazilLow.json` / `brazilHigh.json` were not parsed, so the exact feature count (26 states, 27 with DF, or something else) was not counted. Sizes are for geodata 5.1.5, while the download page's current geodata version is 5.1.6.
- echarts-countries-js Brazil resolution was not opened.
- ApexMaps' exact registry id string for Brazil (for example `br` versus `brazil`) was not copied from the catalogue. The README names Brazil in the admin-1 list only.

## For ECharts specifically: how does registerMap work, and is the library Apache-2.0 in 2026?

### Takeaway
Yes. The package published on npm as 6.1.0, about five months before 2026-10-08, is Apache-2.0, and the README still says Apache License V2. `registerMap` stores a GeoJSON or SVG document under a string name. A `map` series or `geo` component then sets `map` to that name. The library does not include Brazil or world polygons. No fee, watermark, or non-commercial clause was found.

### Cited Findings
- npm page for `echarts`: version 6.1.0, license `Apache-2.0`, "Published 5 months ago" relative to the fetch on 2026-10-08, so the release is around May 2026. Weekly downloads on that page: 4,328,472. README: "ECharts is available under the Apache License V2." Description: "a free, powerful charting and visualization library" for "commercial products." — [npm echarts](https://www.npmjs.com/package/echarts)
- The API page fetched via search (echarts.apache.org/api.html, published timestamp 2026-09-01) documents `registerMap` as usable only after a geo component or a map series is in play. Parameters: `mapName` (the string you later put in `geo.map` or the map series), `opt.geoJSON` (object or JSON string; alias `geoJson`), optional `specialAreas` to reposition pieces such as Alaska, and an alternate form that registers an SVG. The sample call is `echarts.registerMap('my_geo_sample', {geoJSON: geoJSONSample})`. Another documented form is `echarts.registerMap('USA', usaJson, { Alaska: { left, top, width }, ... })`. `getMap(mapName)` returns `{ geoJSON, specialAreas }`. SVG maps cannot be read back that way yet. — [API](https://echarts.apache.org/api.html)
- Same page: "If you only import the required components in your project, starting from v5.3.0 `registerMap` cannot be called unless `MapChart` or `GeoComponent` is imported." — [API](https://echarts.apache.org/api.html)
- Official examples load a GeoJSON file and then call `echarts.registerMap('iceland', geoJSON)` before `setOption`. There is no registry account. — [echarts-examples README](https://github.com/apache/echarts-examples)
- The v4 download-map page still says map data is not included and points at third-party base maps. That page is old (it also suggests Baidu Map). It matches the current API in one respect: polygons are not in the core library. It should not be read as the v6 way to draw a choropleth; v6 uses `registerMap` plus the `map` series. — [download-map](https://echarts.apache.org/en/download-map.html); [API](https://echarts.apache.org/api.html)
- Script use without a bundler: the npm README points at the jsDelivr CDN for the package. Package metadata gives `unpkg` and `jsdelivr` as `dist/echarts.min.js`. Full-file size at 6.1.0 is 1,114,829 bytes minified, 367,958 gzip. — [npm readme](https://www.npmjs.com/package/echarts); [bundlephobia API](https://bundlephobia.com/api/size?package=echarts@6.1.0)
- Maintenance: 6.1.0 is a 2026 npm release (five months before 2026-10-08). The API HTML carried a 2026-09-01 timestamp. The examples repo is still published under Apache-2.0. — [npm](https://www.npmjs.com/package/echarts); [API](https://echarts.apache.org/api.html); [echarts-examples](https://github.com/apache/echarts-examples)
- echarts-countries-js is not the official map registry. README: "This projects is NOT associated with official Apache ECharts." Latest npm 1.0.5 was published 2022-02-13. GitHub `package.json` says version 1.0.6 and license ISC; LICENSE.md says ODbL-1.0. It does include a Brazil script. It is not required for `registerMap`. — [GitHub](https://github.com/echarts-maps/echarts-countries-js); [npm](https://www.npmjs.com/package/echarts-countries-js); [LICENSE.md](https://github.com/echarts-maps/echarts-countries-js/blob/master/LICENSE.md)

### Inferences
- A static HTML report can load `echarts.min.js` from a script tag, `fetch` an IBGE municipality GeoJSON, call `echarts.registerMap('municipios', geojson)`, and set the series `map` to `'municipios'`. Names on features come from GeoJSON `properties.name` in the documented sample (`"name": "Some Place"`). Matching IBGE names or codes to series data is done in that properties field; the core library does not ship an IBGE id list.
- Apache-2.0 in 2026 is the published npm license, not only a historical label. Redistributing the minified file inside generated HTML is within what that license id is known to allow, and no Highcharts-style non-commercial rider was found on the ECharts pages.
- Because polygons are not bundled, the Brazil map "resolution" of ECharts itself is none. Resolution is whatever GeoJSON you register. A world choropleth likewise needs a world GeoJSON you supply. echarts-countries-js is one unofficial source of country files, with a stale release and a conflicting license id.

### Gaps
- The exact 6.1.0 release date (day) was not copied from the GitHub release page. "About May 2026" is the npm "5 months ago" label as of 2026-10-08.
- A map-only custom build size for 6.1.0 was not produced. The v4 builder is not a measure of the v6 file.
- Feature property used as the join key (`name` versus another field) was taken from the sample GeoJSON in the API page, not from a dedicated "IBGE" example. An IBGE file whose names live under a different property was not tested.
- The official site's machine-readable docs index (`https://echarts.apache.org/en/llms.txt`) was not fetched after the English API URL redirected to a stub. The registerMap text used here is from the search snapshot of `https://echarts.apache.org/api.html` dated 2026-09-01.
